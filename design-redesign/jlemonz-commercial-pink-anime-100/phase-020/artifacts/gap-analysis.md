# Foundation Gap Analysis

## Hard Blockers

None.

## Soft Gaps

### Visual Richness

The current Astro pages are still a skeleton. They prove the route, token, type, and accessibility foundation, but they do not yet satisfy the final "commercial anime diary" visual bar. This is expected. Phase 021 begins the actual visual implementation.

### Real API Integration

The adapter layer and route compatibility exist, but later phases must wire more components to real API responses and verify empty, loading, error, and success states.

### Search Modal

The search entry has accessible button semantics, but the actual search overlay is not implemented yet. That starts later at the search phases.

### Comment and Reaction UI

The protected backend endpoints remain untouched, but the new Astro UI has not implemented the final comment and reaction experience yet.

### Asset Optimization

Asset inventory is complete enough to proceed. Later background and image phases must still optimize responsive formats and avoid shipping oversized originals blindly.

## Required Fixes Before Phase 021

None.

## Carry-Forward Notes

- Do not interpret the current skeleton as the target visual quality.
- Do not deploy the Astro output to the live static root yet.
- Do not weaken the accessibility baseline when adding decorative anime layers.
- Do not let future background work reintroduce moving viewport drift.
